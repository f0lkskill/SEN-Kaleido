# SEN-Kaleido 算法实现组实施方案

> 课题：特殊教育生成式智能学习资源开发与课堂应用研究
> 角色：AI 模型构建与算法实现组
> 版本：v1.2（云端大模型选型与目录调整版）

---

## 一、项目定位与核心目标

**定位**：面向特殊教育的模块化、多指标、个性化生成式 AI 引擎（非商用）。

**核心目标**：打通"多维学情画像 → Prompt 引擎生成 → 规则+云端评分校验 → 个性化匹配分发 → 课堂反馈迭代"的业务闭环，产出可直接供试点学校使用的多模态资源生成工具库。

**技术基调**：不做"通用大模型全自动生成"的过度承诺，定位为**可落地、可解释、教师可干预**的半自动工程体系。

## 二、部署形态与系统架构

### 2.1 部署形态：局域网 C/S + 处理基站

系统采用**局域网客户端/服务器架构**：

- **处理基站**：在教室局域网内运行的 Bottle 服务，是核心处理节点，也是**唯一的数据写入方**。所有云端大模型调用、资源生成、质检、数据落盘都集中在基站完成。
- **教室机客户端**：纯 **HTML + JS** 静态页面，浏览器直接访问基站地址，负责任务提交、状态轮询、资源浏览。无需 Node 构建工具，部署成本极低。
- **组网价值**：一台处理基站即可支撑多间教室同步使用，资源与学情数据天然集中，便于统一管理与后续统计。

### 2.2 实时性取舍：后处理模型

云端大模型调用存在网络往返与推理延迟，且易触发限流，因此：

- **舍弃实时更新**：生成与质检不走同步请求。
- **改为后处理**：客户端提交任务后立即返回任务 ID，后台线程异步处理；客户端通过轮询任务状态获取结果。
- 该模型同时天然容纳质检不通过后的自动重新生成（Retry）与批量处理。

### 2.3 模型选型与能力边界

主模型选用 **DeepSeek-V4.1-Flash**（官方模型名 `deepseek-flash`），通过 OpenAI 兼容接口（`https://api.deepseek.com`）调用。

**选型理由**：
- 中文能力与通用推理强，适合特教文本资源生成。
- 1M 上下文、384K 最大输出，能承载完整课件/教案的一次性生成。
- 原生支持 JSON Output 与 Tool Calls，便于结构化资源与流程编排。
- 价格低，且峰谷定价（闲时半价）。

**能力映射**：

| 用途 | 方案 | 说明 |
|---|---|---|
| 文本生成（课件 / 题库 / 教案） | `deepseek-flash` | 核心生成能力 |
| 质检云端打分（含图文审查） | `deepseek-flash` | 视觉理解 + JSON 结构化评分 |
| 图像生成 | 第三方文生图（可降级） | DeepSeek 不具备图像生成能力 |
| 语音合成 | Edge-TTS（免费）或云端 TTS | DeepSeek 无 TTS 能力 |

**能力边界（关键）**：V4.1 Flash 的原生多模态是**视觉理解**——支持"图片进、文字出"，可用于图片分析、学生作业/视觉素材审查，但**不支持图像生成**。因此多模态康复素材、课件配图等图片类产出需另接文生图服务；在经费或合规受限时，降级为符号画、图库检索或占位图。

**峰谷定价调度**：DeepSeek 闲时（夜间、周末及法定节假日全天）价格为高峰时段的一半。本系统已舍弃实时生成、改为后处理，可将批量生成任务调度到闲时执行，**生成成本直接减半**，同时避开高峰限流。任务调度策略由 `kaleido-tasks` 实现。

### 2.4 五层模块化设计

系统按数据流向划分为五大核心子模块，另设三个支撑模块：

| 模块 | 中文名 | 输入 | 输出 |
|---|---|---|---|
| `kaleido-profile` | 学情画像层 | 障碍类型、认知等级、感官偏好、康复目标 | 标准化学情标签向量（JSON） |
| `kaleido-forge` | 多模态生成层 | 学情标签 + 资源类型 + 教学内容 | 课件 / 题库 / 康复素材 / 教学方案 |
| `kaleido-facet` | 质量校验层 | 生成资源原文 | 适配度得分（0–100）+ 校验报告 |
| `kaleido-match` | 个性化匹配层 | 学情标签 + 资源库 | 按适配度排序的资源推荐列表 |
| `kaleido-loop` | 反馈迭代层 | 课堂使用数据 | 待优化池 + 优化建议报告 |
| `kaleido-tasks` | 异步任务层（支撑） | 生成/质检/迭代请求 | 任务队列、状态与闲时调度 |
| `kaleido-vault` | 资源库（支撑） | 资源与元数据 | JSON 文档库存储与检索 |
| `kaleido-guard` | 合规保障（支撑） | 生成与分发请求 | API 密钥管理、内容安全、教师确认门 |

数据总线：各模块通过 `kaleido-common` 中定义的数据模型（dataclass / Pydantic）通信，互不直接耦合。

## 三、各模块详细设计

### 3.1 kaleido-profile（学情画像层）

**职责**：将特殊学生的非结构化描述转化为可计算的标准化标签向量。

**画像维度**：

| 维度 | 取值示例 |
|---|---|
| 障碍类型 | 视力障碍 / 听力障碍 / 智力障碍 / 自闭症 |
| 障碍程度 | 轻度 / 中度 / 重度 |
| 认知等级 | 学段 + 认知水平等级 |
| 感官偏好 | 视觉优先 / 听觉优先 / 触觉辅助 / 图文结合 |
| 康复目标 | 语言 / 感统 / 社交 / 认知训练 |
| 学习节奏 | 快 / 中 / 慢（配合碎片化/连续化） |

**实现要点**：
- 采用配置驱动（YAML/JSON）而非硬编码，教师可不写代码调整适配参数。
- 输出统一 JSON 标签向量，作为下游所有模块的输入契约。
- 建立分层规则引擎 + 可配置 Prompt 模板映射关系。
- 数据以 JSON 文档形式存入 `kaleido-vault`。

### 3.2 kaleido-forge（多模态生成层）

**职责**：核心生成引擎，通过 `deepseek-flash` 与多模态工具产出资源。

**云端调用**：
- 使用 `requests` 直调 DeepSeek OpenAI 兼容接口，不引入 LangChain/LlamaIndex 等重依赖。
- 统一封装为 `llm_client`，集中管理 base_url、model（默认 `deepseek-flash`）、密钥与思考强度。
- 调用参数（温度、最大长度、超时、重试、是否 JSON Output）由 `configs/` 集中管理。
- 批量任务交由 `kaleido-tasks` 调度至闲时执行，降低成本与限流风险。

**分层 Prompt 模板工程**：
- 为视障、听障、智障、自闭症四大类学生建立独立模板库，使用 Jinja2 动态拼装。
- 视障示例约束：`{"format": "voice_first", "sentence_length": "<15", "avoid_visual_ref": true}`
- 智障示例约束：`{"step_by_step": true, "add_emoji": true}`

**知识增强**：
- 维护本地特教知识库（课标、康复手册、盲文规则等），以 JSON 存储。
- 生成题库与个别化方案前先检索相关知识注入 Context，缓解专业术语幻觉。

**五大类资源产出**（对应申报书要求）：
1. 分层知识点课件
2. 个性化练习题库
3. 多模态康复素材（文本由 Flash 生成，图片走第三方文生图或降级）
4. 课堂互动辅助资源
5. 个别化教学方案模板

**流水线**：需求分析 → Prompt 拼装 → 云端生成 → 适配优化 → 审核打磨 → 迭代更新，全程由 `kaleido-tasks` 异步调度。

### 3.3 kaleido-facet（质量校验层）

**职责**：自动拦截劣质资源，输出适配度得分，是课题答辩的技术亮点。

**双通道校验**：

| 通道 | 内容 | 技术 |
|---|---|---|
| 规则层 | 句子平均长度、Flesch 阅读易读度、生僻字比例、视觉元素丰富度 | 本地 Python 规则，零成本、零延迟，做硬性拦截 |
| 模型层 | 按障碍类型撰写评分 Prompt，由 `deepseek-flash` 输出适配度得分与扣分理由，支持图文一起送审 | `requests` 调用云端大模型，JSON Output 返回结构化评分 |

**拦截策略**：规则层不通过直接打回；模型层得分低于阈值（默认 60 分）自动进入重新生成队列，并记录拦截日志与评分理由。

### 3.4 kaleido-match（个性化匹配层）

**职责**：冷启动条件下的混合推荐。

**策略权重**：
- 基于内容的匹配（学生画像标签与资源标签的相似度）—— 权重 70%
- 协同过滤（试点学校教师选用记录）—— 权重 30%
- 硬性规则兜底：如绝对不给重度听障生推荐无字幕纯音频。

**检索实现**：因改用 JSON 存储，`match` 在基站启动时把资源标签加载进内存建立索引，写入后增量更新，避免每次全量扫描。

**核心要求**：推荐结果可解释，教师能理解"为什么推荐这个资源"。

### 3.5 kaleido-loop（反馈迭代层）

**职责**：采集课堂反馈并触发资源迭代。

**数据采集**：课堂参与度标记、教师快速评分、学生完成度、资源播放时长、错题率、教师修改率。

**迭代触发（配置驱动）**：定义可调整阈值规则，如"连续 3 次教师评分 < 3 分 → 标记待优化"，JSON 记录资源使用轨迹，生成优化建议报告。

**设计原则**：不做全自动，采用"AI 建议 + 教师确认"的人机协同模式。

### 3.6 kaleido-tasks（异步任务层）

**职责**：支撑"提交-轮询"的后处理模型与闲时调度。

- 内存任务队列 + 后台工作线程（基站唯一写入方，天然串行落盘）。
- 任务状态（排队 / 处理中 / 完成 / 失败）持久化到 JSON，基站重启可恢复。
- **闲时调度**：批量生成任务可配置为在 DeepSeek 闲时时段执行，成本减半。
- 对外提供任务提交与状态查询接口。

### 3.7 kaleido-vault（资源库）

- 改用**本地 JSON 文档库**，按资源/画像/反馈分类、按 ID 分片存储。
- 写入集中在基站单线程/加锁（`portalocker`）执行，避免多教室并发写导致丢数据。
- 提供 REST 接口供教室机读写；启动时构建内存索引供检索。

### 3.8 kaleido-guard（合规保障）

- **云端 API 密钥管理**：密钥只存于基站，不下发客户端。
- **用量与成本监控**：统计 token 消耗、闲时/高峰分布，设置限额。
- 内容安全与敏感词过滤。
- 教师确认门：所有生成结果必须经教师确认方可进入课堂。
- 使用边界声明：明确 AI 辅助育人定位，禁止过度替代教师。

## 四、关键技术策略

1. **分层 Prompt 模板工程**：不训练模型，靠工程化解决适配。
2. **云端大模型 + 本地知识库增强**：解决专业术语幻觉，同时避免本地推理。
3. **"规则 + 云端大模型评分"双重质检**：规则负责硬性拦截，模型负责软性评分，兼顾成本、可解释性与算法贡献。
4. **冷启动混合推荐**：内容过滤为主、协同过滤为辅、规则兜底。
5. **异步后处理 + 闲时调度 + 配置驱动迭代**：以任务队列吸收云端延迟，以峰谷定价降低生成成本，以阈值规则实现可解释迭代。

## 五、技术栈选型

| 模块 | 技术/工具 | 理由 |
|---|---|---|
| 后端语言 | Python 3.10+ | AI 生态与网络调用最便利 |
| Web 框架 | Bottle | 单文件轻量，适合局域网基站 |
| WSGI 服务器 | waitress | 纯 Python 多线程，承载多教室并发 |
| 前端 | 原生 HTML + JS | 无需构建，教师端零安装 |
| LLM 接入 | `requests` 直调 DeepSeek `deepseek-flash` | 依赖最少，OpenAI 兼容 |
| 质量校验 | 规则引擎 + `deepseek-flash` 评分 Prompt | 无本地推理，成本与效果平衡 |
| 图像生成 | 第三方文生图（可降级为符号画/图库） | 补足 DeepSeek 无图像生成的缺口 |
| 语音合成 | Edge-TTS / 云端 TTS | 补足 DeepSeek 无 TTS 的缺口 |
| 存储 | 本地 JSON 文档库 | 需求明确为本地 JSON，便于接口化访问 |
| 并发控制 | portalocker / 单写线程 | 防止并发写丢失 |
| 异步任务 | 内存队列 + 后台线程 + 闲时调度 | 实现后处理模型与成本优化 |
| 工程 | ruff / pytest | 代码质量与测试 |

## 八、风险预警与对策

| 风险 | 对策 |
|---|---|
| 云端调用延迟 / 限流 | 全面后处理化，异步任务队列 + 超时重试 + 结果缓存 + 闲时调度避峰 |
| DeepSeek 无法生成图像 / 语音 | 图像接第三方文生图或降级为符号画/图库；语音用 Edge-TTS；文档中明确能力边界，避免过度承诺 |
| 云端 API 费用不可控 | 集中密钥管理、token 用量统计与限额、闲时调度成本减半、低成本模型优先、批量合并请求 |
| 网络中断导致无法生成 | 基站本地缓存历史资源与知识库，断网时仍可浏览、匹配、统计；生成功能降级提示 |
| JSON 并发写丢数据 | 基站为唯一写入方，单写线程 + 文件锁 + 分片存储 |
| Bottle 并发能力不足 | 使用 waitress 多线程承载，避免默认单线程 wsgiref |
| 特教教师对 AI 生成信任度低 | 遵循 Human-in-the-loop，支持段落级修改与重新生成，提供"一键替换同义词/简化句子"按钮 |
| 效果量化评价困难（课题难点） | 不承诺"提升康复效果"，配合教研组埋点，客观记录播放时长、错题率、教师修改率，提供可视化报表 |
| 技术过度替代教师 | `kaleido-guard` 强制教师确认门，划定技术应用边界 |

## 十、技术边界与合规

- 算法组**不负责**课堂应用策略设计（教研组职责）与资源审核标准制定（特教专家职责）。
- 算法组交付：可调用的生成 API、可配置的适配规则引擎、可查看的资源质量报告。
- 明确定位为"教师可调控的半自动适配工具"，不承诺"全自动精准适配"。
- 效果评价不构建"效果评估模型"，仅提供统计描述与可视化能力。
