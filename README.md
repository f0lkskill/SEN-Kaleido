# SEN-Kaleido

**模块化 · 多指标 · 个性化 · 多模态**

面向特殊教育的生成式 AI 资源引擎——输入多维学情指标，折射出每个学生专属的学习图案。

---

## 项目简介

SEN-Kaleido 是面向特殊教育的模块化生成式 AI 引擎。它将多维学情画像（障碍类型、认知水平、感官偏好、康复目标）与可配置的生成流水线结合，产出分层课件、个性化题库、多模态康复素材与个别化教学方案。与通用 AI 工具不同，SEN-Kaleido 把"适配"视为多指标、教师可调控的过程：每份资源都在明确的无障碍与认知负荷约束下生成，经自动化质量校验，并通过课堂反馈闭环持续迭代。

本仓库是课题《特殊教育生成式智能学习资源开发与课堂应用研究》中**AI 模型构建与算法实现组**的核心工程载体。

## 核心特点

- **模块化**：按"学情画像 → 多模态生成 → 质量校验 → 个性化匹配 → 反馈迭代"数据流拆分为五个独立子模块，可独立交付、替换与组合。
- **多指标**：障碍类型、认知等级、感官偏好、康复目标等多维指标统一编码为可计算的学情标签向量。
- **个性化**：以障碍类型与认知层级为约束，为不同学生折射出专属的资源组合。
- **多模态**：文本、语音、图像等多形态学习资源统一生成与适配。
- **人机协同**：所有生成结果支持段落级修改与重新生成，教师始终拥有确认权。

## 部署形态

采用**局域网 C/S 架构**：一台**处理基站**在教室局域网内运行核心服务，多台教室机通过浏览器访问。基站是唯一的写入方，数据集中落盘、集中对外调用云端大模型，教室机只负责提交任务与浏览结果。

- 客户端：纯 **HTML + JS** 静态客户端，浏览器直接打开基站地址，无需构建工具。
- 服务端：**Bottle** 轻量服务，配合 **waitress** 多线程 WSGI 承载多教室并发访问。
- 推理：**云端大模型 API**，舍弃本地推理。
- 实时性：因云端调用存在延迟，**舍弃实时更新，改为后处理**——提交任务后由后台异步处理，客户端轮询任务状态。
- 存储：**本地 JSON 文档库**，通过接口 API 供教室机访问。

## 模型策略

主模型选用 **DeepSeek-V4.1-Flash**（官方模型名 `deepseek-flash`），通过 OpenAI 兼容接口调用。

**能力覆盖**：

| 用途 | 方案 | 说明 |
|---|---|---|
| 文本生成（课件 / 题库 / 教案） | `deepseek-flash` | 中文强、1M 上下文、384K 输出、支持 JSON Output 与 Tool Calls |
| 质检云端打分（含图文审查） | `deepseek-flash` | 原生多模态视觉理解，可对图文资源给出适配度与扣分理由 |
| 图像生成 | 第三方文生图（可降级） | **V4.1 Flash 仅支持视觉理解，不能生成图像**，图片类素材需另接文生图服务，或降级为符号画 / 图库检索 |
| 语音合成 | Edge-TTS（免费）或云端 TTS | DeepSeek 无 TTS 能力，视障"语音优先"资源需外部 TTS |

**能力边界提醒**：V4.1 Flash 的"视觉"是**图片进、文字出**的理解能力，可用作图片分析、视觉素材审查，但**不具备图像生成能力**。

**峰谷调度**：DeepSeek 采用峰谷定价，闲时（夜间、周末、法定节假日）价格为高峰时段的一半。本系统已舍弃实时生成、改为后处理，因此可将批量生成任务调度到闲时执行，**生成成本直接减半**。

## 模块说明

| 模块 | 中文名 | 职责 |
|---|---|---|
| `kaleido-profile` | 学情画像层 | 将障碍类型（视/听/智/自闭）、认知等级、感官偏好、康复目标转化为标准化学情标签向量 |
| `kaleido-forge` | 多模态生成层 | 核心引擎。基于 Jinja2 分层 Prompt 模板驱动 `deepseek-flash` 等云端能力，产出课件、题库、康复素材、教学方案 |
| `kaleido-facet` | 质量校验层 | 规则引擎（句长、词汇难度、视觉元素）做硬性拦截 + `deepseek-flash` 按评分 Prompt 输出适配度得分 |
| `kaleido-match` | 个性化匹配层 | 基于学情标签与资源标签的混合推荐（内容过滤为主、协同过滤为辅、硬规则兜底） |
| `kaleido-loop` | 反馈迭代层 | 采集课堂使用数据（教师评分、学生完成度），按阈值触发低分资源"回炉重造" |
| `kaleido-tasks` | 异步任务层 | 生成/质检/迭代任务的后处理队列与状态管理，支持闲时调度 |
| `kaleido-vault` | 资源库 | 本地 JSON 文档库，资源元数据、版本管理与检索 |
| `kaleido-guard` | 合规保障 | API 密钥管理、内容安全、使用边界与教师确认门 |

## 技术栈

| 层 | 选型 |
|---|---|
| 语言 | Python 3.10+ |
| Web 服务 | Bottle + waitress（多线程 WSGI） |
| 前端 | 原生 HTML + JS 静态客户端 |
| 模板 | Jinja2 |
| LLM 接入 | `requests` 直调 DeepSeek `deepseek-flash`（OpenAI 兼容接口） |
| 知识增强 | 本地 JSON 知识库 + 关键词/向量检索 |
| 质量校验 | 规则引擎 + `deepseek-flash` 评分 Prompt |
| 图像生成 | 第三方文生图（可降级） |
| 语音合成 | Edge-TTS / 云端 TTS |
| 存储 | 本地 JSON 文档库（分片 + 文件锁） |
| 异步任务 | 内存队列 + 后台线程，任务状态持久化到 JSON |
| 工程 | ruff / pytest |

## 课题背景

本仓库对应课题申报书中"学生学情画像—AI 资源精准匹配—人机协同教学—实时反馈迭代"的课堂应用闭环，重点解决特殊教育资源针对性不足、动态适配性弱、个性化供给缺失、更新迭代滞后等问题。算法组交付内容为：可调用的生成 API、可配置的适配规则引擎、可查看的资源质量报告。

其中"分层知识点课件、个性化练习题库、多模态康复素材、课堂互动辅助资源、个别化教学方案模板"为申报书研究内容二明确要求的五大类核心资源；学生静态属性由建档录入（入学评估 / 教师 / 家长），动态评价数据由 `kaleido-loop` 随教学采集。
